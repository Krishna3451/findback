# Technical comparison with Switch hackathon projects

Reviewed **November 8, 2026**. This is a code review of six public repository snapshots, not a prediction of the judging outcome.

The [official challenge](https://www.wemakedevs.org/hackathons/switch) asks whether Switch is central, whether a reviewer can reproduce the project, whether it addresses a real problem creatively, and whether the presentation explains the Switch integration. Its public page does not provide an accepted-submission directory. Each project below explicitly identifies itself as a Flip the Switch **Business Workflow** entry in its own README. That establishes declared participation, not organizer-confirmed acceptance. FindBack targets **Personal or Creative Workflow**, so these are technical benchmarks across tracks.

I inspected public code, tests, workflow files and documentation from read-only clones. I did **not** execute competitors' tests, install their dependencies, start their services, validate their deployment claims, or independently reproduce their reported evaluation scores. Links pin the inspected commit. All six inspected heads carry commit timestamps before the published November 7 deadline; this does not prove which revision was submitted.

## Ranked concrete opportunities for FindBack

1. **Make failed delivery recoverable without starving new work.** The inspected `SQLiteStore.pending_outbox()` selects the earliest 100 pending/failed records without a due time. A persistent failure can monopolize a batch. Add bounded backoff, retry eligibility and a clearly inspectable terminal/attention state; make explicit operator requeue preserve the original event and deduplication identity. Keep existing uncertain-POST marker reconciliation. Test old permanent failures plus a new valid delivery, restart during backoff, and a post that succeeded before the local acknowledgment was saved. This is an actual gap observed in FindBack, not a feature copied from a competitor. Implementation was in progress during this review; reassess the final source before calling it outstanding.

2. **Give operators one redacted health and recovery report.** Build on existing `doctor` and SQLite journals: show enrolled connection liveness, cursor/generation, pending/failed inbox and outbox totals, oldest work age, bounded attempt counts and safe error codes. Include actionable recovery instructions for replay gaps, authentication failure and uncertain delivery. Keep claimant evidence, message bodies and credentials out. Vigil's inspection surface is the benchmark; a new frontend is unnecessary.

3. **Publish an independently reproducible end-to-end proof.** Locked unit CI is necessary but weaker than Overruled's clean-stack trial. Add an opt-in real-Switch smoke command or manually triggered isolated CI job that creates fresh fictional accounts/rooms, tests actual cross-room access refusals, completes one recovery and checks the authoritative final state. Publish a redacted machine-readable report with source revision and environment versions. Keep scripted people, model calls, physical handover and production adoption distinct. Existing FindBack live evidence should be reusable rather than replaced.

4. **Add a small, versioned evidence-quality evaluation.** Extend existing domain/model tests with labelled scenarios: indistinguishable items, contradictory distinctive facts, absent facts, misleading urgency, quoted commands, changed evidence after inference, forged approvers and reservation races. Separately report model parsing/grounding quality and deterministic authorization outcomes. Retain misses and a held-out set. Overruled's documented separation of tuned and blind cases is stronger evidence than a large undifferentiated test count.

5. **Render outside text as evidence rather than executable chat formatting.** Audit claimant/model excerpts in report and comparison cards; safely quote Markdown controls and defuse mentions where these could address another agent or page a room. Vigil has a concrete implementation of this boundary. Add a focused rendering regression instead of changing the domain authorization model.

6. **Make a reviewer reach the proof quickly.** Keep the latest demo, truthful endpoint, offline demo, locked test command, setup scope and live-evidence report at the top of the repository. Show what remains planned. Overruled's judge-oriented entry points and honest demo-mode distinctions are worth matching. A hosted static explanation is useful; it should not be described as a hosted agent deployment.

## Strengths to preserve

FindBack already has durable SQLite state, transactions/outbox, exact enrolled actor contexts, evidence/item revision checks, unique reservations and handover-bound receipts. Its Switch client already persists an acknowledgment cursor, fences generations, answers pings independently, refuses replay gaps and treats uncertain writes cautiously. Those are implemented in `src/findback/{domain,storage,runtime,switch_client}.py` with behavioral tests. Adding more named agents, rebuilding reconnect from scratch or weakening authority checks would not improve this comparison.

The strongest next result is a small reliability change with a reproducible failure/recovery test and an operator-visible explanation. The competitors do not establish that a larger agent count or a polished README is a substitute for those properties.

## Implemented follow-up

The November 8 hardening implements persistent due-time retries, failure limits,
blocked delivery states, payload-free queue health and explicit operator requeue
for both queues, including the conversational showcase. It also adds concurrent
input processing with a reserved librarian slot and cancellation-safe replay.
[Operations](OPERATIONS.md), [delivery tests](../tests/test_delivery.py) and
[scheduling tests](../tests/test_scheduling.py) define the verified boundaries.

The locked unit/wheel CI remains configured for Linux and macOS; hosted runners
have not started successfully, so no hosted pass is claimed. The later extension
also implements [fresh-stack verification](FRESH_STACK_E2E.md): pinned independent
Core/Mattermost/PostgreSQL services, controlled-model and actual-Codex runs,
22 scenario checks plus 28 access checks, real server replay and verified teardown.

A separately authored, sealed held-out corpus was evaluated against the frozen
production adapter and scorer before the implementation author inspected it.
[First results](../evals/v1/RESULTS.md) retain 17/18 all-check-pass cases and 97/98
narrow probes, with the miss reviewed and unchanged. This closes implementation
opportunities 3 and 4 as bounded local proofs; it does not establish a population
accuracy estimate, an externally adjudicated benchmark, a physical return or a
hosted CI result. The original fresh-stack harness failure is retained as well.
